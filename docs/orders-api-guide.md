# Orders API Guide

This guide describes how the frontend should use the authenticated Orders endpoints exposed under:

```text
{API_BASE_URL}/api/v1/orders
```

Example local base URL:

```text
https://localhost:44374/api/v1/orders
```

All endpoints require an access token belonging to a user with the `Buyer` or `Supplier` role.

Send these headers:

```http
Authorization: Bearer {accessToken}
Accept: application/json
Accept-Language: en
Content-Type: application/json
```

`Content-Type` is only required when sending a JSON body. Obtain the access token through the login and OTP flow documented in [auth-api-guide.md](./auth-api-guide.md).

## Important rules

- Buyers list and view only their own orders. Suppliers list and view every order, including closed and Supplier-owned orders.
- Closing remains owner-only. A non-owner receives `404 Not Found`, even when a Supplier can view that order.
- Both Buyers and Suppliers can create and manage their own orders.
- One create request may contain multiple orders. The entire batch succeeds or fails atomically.
- Every order must contain at least one item.
- New orders always have `status: "open"`.
- Closing an order is irreversible and idempotent. It also marks every pending quotation as `closed`.
- `orderNumber` is generated by the server. Numbers are increasing and unique, but gaps are possible.
- Use the order `id` GUID in detail and close URLs. `orderNumber` is a display/search value, not the route identifier.
- Category and classification codes are case-insensitively accepted and stored in canonical lowercase form.
- Omit `classificationCode` or send `null` when the user selects “Any.” Do not send a fake `any` code.
- Dates use `YYYY-MM-DD`.
- Status values returned by the API are lowercase: `open` or `closed`.
- Quotation creation and decisions are documented in [quotation-offers-api-guide.md](./quotation-offers-api-guide.md). Orders cannot be edited, deleted, or reopened.

## Endpoint summary

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/catalog` | Get category and classification codes and bilingual labels |
| `POST` | `/` | Create one or more orders atomically |
| `GET` | `/` | Get the Buyer-owned list or Supplier marketplace list |
| `GET` | `/{id}` | Get an owned order, or any order when called by a Supplier |
| `POST` | `/{id}/close` | Close one owned order |

## 1. Get the order catalog

Load the catalog before rendering category and classification controls:

```http
GET /api/v1/orders/catalog
Authorization: Bearer {accessToken}
```

Response:

```json
[
  {
    "code": "computers-laptops",
    "nameEn": "Computers & Laptops",
    "nameAr": "أجهزة كمبيوتر ولاب توب",
    "classifications": [
      {
        "code": "screens",
        "nameEn": "Screens",
        "nameAr": "شاشات"
      },
      {
        "code": "accessories",
        "nameEn": "Accessories",
        "nameAr": "ملحقات"
      }
    ]
  }
]
```

The complete current catalog is:

| Category code | English | Arabic | Classification codes |
| --- | --- | --- | --- |
| `computers-laptops` | Computers & Laptops | أجهزة كمبيوتر ولاب توب | `screens`, `accessories`, `storage`, `smartphones`, `tablets`, `audio`, `chargers` |
| `networking-infrastructure` | Networking & Infrastructure | قسم الشبكات والبنية التحتية | `servers` |
| `printers-ink` | Printers & Ink | طابعات أحبار وورق | `printers`, `ink-printers` |
| `services-maintenance` | Services & Maintenance | قسم الخدمات والصيانة | None |

Use `nameAr` when the active locale is Arabic and `nameEn` otherwise. Submit `code`, never a translated label.

When the selected category changes, clear a classification that does not belong to the new category.

## 2. Create orders

```http
POST /api/v1/orders
Authorization: Bearer {accessToken}
Content-Type: application/json
```

Request with one order:

```json
{
  "orders": [
    {
      "categoryCode": "computers-laptops",
      "classificationCode": "screens",
      "title": "Office monitors",
      "deliveryDate": "2026-10-15",
      "items": [
        {
          "name": "27-inch monitor",
          "quantity": 10,
          "details": "4K IPS display with HDMI and DisplayPort"
        },
        {
          "name": "Monitor arm",
          "quantity": 10,
          "details": "Adjustable desk-mounted arm"
        }
      ]
    }
  ]
}
```

Request with multiple orders:

```json
{
  "orders": [
    {
      "categoryCode": "computers-laptops",
      "classificationCode": null,
      "title": "General computer equipment",
      "deliveryDate": "2026-10-15",
      "items": [
        {
          "name": "Laptop",
          "quantity": 5,
          "details": "16 GB RAM, 512 GB SSD or better"
        }
      ]
    },
    {
      "categoryCode": "services-maintenance",
      "title": "Quarterly network maintenance",
      "deliveryDate": "2026-10-20",
      "items": [
        {
          "name": "Maintenance visit",
          "quantity": 1,
          "details": "Inspect switches, access points, and cabling"
        }
      ]
    }
  ]
}
```

For an “Any” classification, either omit the property:

```json
{
  "categoryCode": "computers-laptops",
  "title": "General equipment"
}
```

or send:

```json
{
  "classificationCode": null
}
```

Successful response:

```json
{
  "orders": [
    {
      "id": "7e0a721a-13bd-48c4-a719-183ea72bc03a",
      "orderNumber": 1000,
      "categoryCode": "computers-laptops",
      "categoryNameEn": "Computers & Laptops",
      "categoryNameAr": "أجهزة كمبيوتر ولاب توب",
      "classificationCode": "screens",
      "classificationNameEn": "Screens",
      "classificationNameAr": "شاشات",
      "title": "Office monitors",
      "deliveryDate": "2026-10-15",
      "status": "open",
      "creationTime": "2026-09-02T09:30:00Z",
      "lastModificationTime": null,
      "items": [
        {
          "id": "b82257ea-fe50-40ac-b59b-ad741cfe11aa",
          "name": "27-inch monitor",
          "quantity": 10,
          "details": "4K IPS display with HDMI and DisplayPort"
        }
      ]
    }
  ]
}
```

Do not send server-controlled properties such as `id`, `orderNumber`, `status`, `userId`, or creation timestamps. Unknown properties are rejected.

### Create validation

Each request must satisfy all of these rules:

- `orders` must contain at least one order.
- `categoryCode` must match a catalog category.
- `classificationCode` is optional, but it must belong to the selected category when supplied.
- `title` is required and cannot exceed 256 characters.
- `deliveryDate` cannot be earlier than the current UTC date.
- `items` must contain at least one item.
- Item `name` is required and cannot exceed 256 characters.
- Item `quantity` must be a positive integer.
- Item `details` is required and cannot exceed 2,000 characters.

If any order or item is invalid, the API returns `400 Bad Request` and stores none of the orders in that request.

## 3. List orders

```http
GET /api/v1/orders
Authorization: Bearer {accessToken}
```

The result uses the ABP paged response shape:

```json
{
  "totalCount": 2,
  "items": [
    {
      "id": "7e0a721a-13bd-48c4-a719-183ea72bc03a",
      "orderNumber": 1000,
      "categoryCode": "computers-laptops",
      "categoryNameEn": "Computers & Laptops",
      "categoryNameAr": "أجهزة كمبيوتر ولاب توب",
      "classificationCode": null,
      "classificationNameEn": null,
      "classificationNameAr": null,
      "title": "General computer equipment",
      "deliveryDate": "2026-10-15",
      "status": "open",
      "creationTime": "2026-09-02T09:30:00Z",
      "lastModificationTime": null,
      "offerCount": 0,
      "myQuotationId": null,
      "myQuotationStatus": null,
      "quotationActionState": "submit",
      "canSubmitQuotation": true,
      "hasSubmittedQuotation": false,
      "isOwnOrder": false,
      "isOrderClosed": false,
      "items": [
        {
          "id": "b82257ea-fe50-40ac-b59b-ad741cfe11aa",
          "name": "Laptop",
          "quantity": 5,
          "details": "16 GB RAM, 512 GB SSD or better"
        }
      ]
    }
  ]
}
```

Role-sensitive response rules:

- Buyers receive only their own orders. `offerCount` is the number of received offers; Supplier-only fields are `null`.
- Suppliers receive all orders. `quotationActionState` matches the existing UI values: `submit`, `view_submitted`, or `cannot_submit`.
- `myQuotationId` and `myQuotationStatus` identify the current Supplier's immutable offer when one exists.
- `cannot_submit` applies when the Supplier owns the order or the order is closed. `view_submitted` takes precedence when that Supplier already submitted.
- `canSubmitQuotation`, `hasSubmittedQuotation`, `isOwnOrder`, and `isOrderClosed` expose the individual conditions without requiring the frontend to infer them from the combined action value.

### Query parameters

| Parameter | Example | Behavior |
| --- | --- | --- |
| `search` | `monitor` or `1000` | Searches title or order number |
| `categoryCode` | `computers-laptops` | Exact category-code filter |
| `classificationCode` | `screens` | Exact classification-code filter |
| `status` | `open` | Accepts only `open` or `closed` |
| `date` | `2026-10-15` | Matches either creation date or delivery date |
| `skipCount` | `0` | Number of records to skip |
| `maxResultCount` | `10` | Maximum records to return |
| `sorting` | `deliveryDate desc` | Allow-listed field and optional direction |

Examples:

```http
GET /api/v1/orders?search=monitor&status=open&skipCount=0&maxResultCount=10
```

```http
GET /api/v1/orders?categoryCode=computers-laptops&classificationCode=screens&sorting=deliveryDate%20asc
```

```http
GET /api/v1/orders?date=2026-10-15&sorting=orderNumber%20desc
```

Allowed sorting fields:

- `creationTime`
- `deliveryDate`
- `orderNumber`
- `title`

Directions are `asc` and `desc`. If `sorting` is omitted, results are ordered by newest creation time first, then highest order number.

Unsupported sorting fields or directions return `400 Bad Request`. Never pass arbitrary UI column names directly to `sorting`; map them to this allow-list.

## 4. Get order details

Use the order's GUID `id`, not its numeric `orderNumber`:

```http
GET /api/v1/orders/7e0a721a-13bd-48c4-a719-183ea72bc03a
Authorization: Bearer {accessToken}
```

The response uses the complete order shape shown in the create response, including bilingual catalog labels, timestamps, status, and complete item details.

For Buyers, the API returns `404 Not Found` when the ID does not exist or belongs to another user. Suppliers may view any existing order, but still receive `404` for a missing ID.

Closing returns `404 Not Found` when:

- The ID does not exist.
- The order belongs to another user.

Treat both cases identically in the UI.

## 5. Close an order

```http
POST /api/v1/orders/7e0a721a-13bd-48c4-a719-183ea72bc03a/close
Authorization: Bearer {accessToken}
```

No request body is required.

Response:

```json
{
  "id": "7e0a721a-13bd-48c4-a719-183ea72bc03a",
  "orderNumber": 1000,
  "categoryCode": "computers-laptops",
  "categoryNameEn": "Computers & Laptops",
  "categoryNameAr": "أجهزة كمبيوتر ولاب توب",
  "classificationCode": "screens",
  "classificationNameEn": "Screens",
  "classificationNameAr": "شاشات",
  "title": "Office monitors",
  "deliveryDate": "2026-10-15",
  "status": "closed",
  "creationTime": "2026-09-02T09:30:00Z",
  "lastModificationTime": "2026-09-02T10:00:00Z",
  "items": []
}
```

The real response retains all of the order's items; the empty array above is abbreviated for readability.

Calling the close endpoint again returns `200 OK` with the already-closed order. There is no reopen endpoint.
The first close also changes all of that order's pending quotations to `closed`; accepted and declined history is unchanged.

## Authentication and error statuses

| Status | Meaning |
| --- | --- |
| `400 Bad Request` | Validation, catalog, filter, or sorting error |
| `401 Unauthorized` | Access token is absent, invalid, or expired |
| `403 Forbidden` | Authenticated user does not have the Buyer or Supplier role |
| `404 Not Found` | Order does not exist, or an owner-only operation targets another user's order |

Example validation response:

```json
{
  "code": 400,
  "message": "Validation failed.",
  "status": 400,
  "title": "One or more validation errors occurred.",
  "details": "One or more order validation errors occurred.",
  "errors": {
    "Orders[0].DeliveryDate": [
      "Orders[0].DeliveryDate Delivery date cannot be earlier than the current UTC date."
    ]
  }
}
```

Display useful server validation messages, but drive application behavior primarily from the HTTP status and request context.

## cURL examples

Set your current access token first:

```bash
ACCESS_TOKEN="jwt-access-token"
API_BASE_URL="https://localhost:44374"
```

Get the catalog:

```bash
curl "$API_BASE_URL/api/v1/orders/catalog" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Accept: application/json"
```

Create an order:

```bash
curl -X POST "$API_BASE_URL/api/v1/orders" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "orders": [
      {
        "categoryCode": "networking-infrastructure",
        "classificationCode": "servers",
        "title": "Application server",
        "deliveryDate": "2026-10-15",
        "items": [
          {
            "name": "Rack server",
            "quantity": 2,
            "details": "Redundant power supplies and remote management"
          }
        ]
      }
    ]
  }'
```

List orders:

```bash
curl "$API_BASE_URL/api/v1/orders?status=open&sorting=creationTime%20desc&skipCount=0&maxResultCount=10" \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Close an order:

```bash
curl -X POST "$API_BASE_URL/api/v1/orders/7e0a721a-13bd-48c4-a719-183ea72bc03a/close" \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

## TypeScript contracts

```ts
export type OrderStatus = "open" | "closed";

export interface OrderCatalogClassification {
  code: string;
  nameEn: string;
  nameAr: string;
}

export interface OrderCatalogCategory {
  code: string;
  nameEn: string;
  nameAr: string;
  classifications: OrderCatalogClassification[];
}

export interface CreateOrderItem {
  name: string;
  quantity: number;
  details: string;
}

export interface CreateOrder {
  categoryCode: string;
  classificationCode?: string | null;
  title: string;
  deliveryDate: string; // YYYY-MM-DD
  items: CreateOrderItem[];
}

export interface OrderItem {
  id: string;
  name: string;
  quantity: number;
  details: string;
}

export interface Order {
  id: string;
  orderNumber: number;
  categoryCode: string;
  categoryNameEn: string;
  categoryNameAr: string;
  classificationCode: string | null;
  classificationNameEn: string | null;
  classificationNameAr: string | null;
  title: string;
  deliveryDate: string;
  status: OrderStatus;
  creationTime: string;
  lastModificationTime: string | null;
  offerCount: number;
  myQuotationId: string | null;
  myQuotationStatus: "pending" | "accepted" | "declined" | "closed" | null;
  quotationActionState: "submit" | "cannot_submit" | "view_submitted" | null;
  canSubmitQuotation: boolean;
  hasSubmittedQuotation: boolean;
  isOwnOrder: boolean;
  isOrderClosed: boolean;

  orders: Order[];
}

  totalCount: number;

}
```

## Minimal TypeScript client

```ts
const apiBaseUrl = process.env.NEXT_PUBLIC_API_URL;

async function orderRequest<T>(
  path: string,
  accessToken: string,
  init?: RequestInit,
): Promise<T> {
  const response = await fetch(`${apiBaseUrl}${path}`, {
    ...init,
    headers: {
      Accept: "application/json",
      "Accept-Language": "en",
      Authorization: `Bearer ${accessToken}`,
      ...(init?.body ? { "Content-Type": "application/json" } : {}),
      ...init?.headers,
    },
  });

  if (!response.ok) {
    const error = await response.json().catch(() => null);
    throw new Error(error?.message ?? `Order request failed (${response.status})`);
  }

  return response.json() as Promise<T>;
}

export function getOrderCatalog(accessToken: string) {
  return orderRequest<OrderCatalogCategory[]>(
    "/api/v1/orders/catalog",
    accessToken,
  );
}

export function createOrders(accessToken: string, orders: CreateOrder[]) {
  return orderRequest<CreateOrdersResponse>("/api/v1/orders", accessToken, {
    method: "POST",
    body: JSON.stringify({ orders }),
  });
}

export interface OrderListQuery {
  search?: string;
  categoryCode?: string;
  classificationCode?: string;
  status?: OrderStatus;
  date?: string;
  skipCount?: number;
  maxResultCount?: number;
  sorting?:
    | "creationTime asc"
    | "creationTime desc"
    | "deliveryDate asc"
    | "deliveryDate desc"
    | "orderNumber asc"
    | "orderNumber desc"
    | "title asc"
    | "title desc";
}

export function getOrders(accessToken: string, query: OrderListQuery = {}) {
  const search = new URLSearchParams();

  Object.entries(query).forEach(([key, value]) => {
    if (value !== undefined && value !== null && value !== "") {
      search.set(key, String(value));
    }
  });

  const suffix = search.size > 0 ? `?${search.toString()}` : "";
  return orderRequest<PagedResult<Order>>(
    `/api/v1/orders${suffix}`,
    accessToken,
  );
}

export function getOrder(accessToken: string, id: string) {
  return orderRequest<Order>(`/api/v1/orders/${id}`, accessToken);
}

export function closeOrder(accessToken: string, id: string) {
  return orderRequest<Order>(`/api/v1/orders/${id}/close`, accessToken, {
    method: "POST",
  });
}
```

```ts
const result = await createOrders(accessToken, formBlocks.map((block) => ({
```
